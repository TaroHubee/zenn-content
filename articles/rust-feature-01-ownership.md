# Rustの所有権・借用・ライフタイムを手を動かして理解する

Rustを始めて最初にぶつかる壁が「所有権」です。他の言語にない概念なので最初は戸惑いますが、一度腑に落ちると「なぜこうなっているのか」がよく分かります。小さなコードを動かしながら順番に理解していきましょう。

---

## 所有権（Ownership）— 値には「持ち主」が1人だけ

Rustでは、全ての値に「持ち主（所有者）」がいます。そして**持ち主は1人だけ**です。

```rust
let s1 = String::from("hello"); // s1 が "hello" を所有
let s2 = s1;                    // 所有権が s2 に移動（ムーブ）
println!("{}", s1);             // ← エラー！s1 はもう無効
```

実行してみると：

```
error[E0382]: borrow of moved value: `s1`
```

「ムーブ後の値は使えない」というエラーです。`s1` から `s2` に所有権が**移動**したため、`s1` は無効になります。

なぜこうなっているのか、メモリの動きから理解してみましょう。

`String` はヒープ（プログラムが動的に使うメモリ領域）に文字列データを置き、スタック上にその「場所（アドレス）・長さ・容量」の情報を持ちます：

```
s1（スタック）          ヒープ
┌──────────────┐       ┌───────────────┐
│ ptr ────────────────▶│ h e l l o     │
│ len = 5      │       └───────────────┘
│ capacity = 5 │
└──────────────┘
```

ここで `let s2 = s1;` をした場合、もし「コピー」されるとしたらこうなります：

```
s1（スタック）          ヒープ
┌──────────────┐       ┌───────────────┐
│ ptr ────────────────▶│ h e l l o     │
│ len = 5      │       └───────────────┘
└──────────────┘               ▲
s2（スタック）                  │
┌──────────────┐               │
│ ptr ──────────────────────────┘
│ len = 5      │
└──────────────┘
```

2つのポインタが**同じメモリを指している**状態です。

`s1` と `s2` が両方スコープを外れると、両方が「このメモリを解放する」と試みます。すると同じメモリが2回解放される「**二重解放（double free）**」が起き、プログラムがクラッシュします。これは C/C++ では実際に起きるバグです。

Rustはこれを防ぐために「**所有権は1人だけ**」というルールを採用しています。`s2 = s1` のとき、所有権は `s2` に**移動（ムーブ）**し、`s1` は無効になります：

```
s1（無効）              ヒープ
┌──────────────┐       ┌───────────────┐
│ （使用不可）  │       │ h e l l o     │
└──────────────┘       └───────────────┘
                               ▲
s2（有効・所有者）             │
┌──────────────┐               │
│ ptr ──────────────────────────┘
│ len = 5      │
└──────────────┘
```

これにより「解放するのは `s2` だけ」が保証され、コンパイル時にクラッシュを防ぎます。

### コピーされる型とムーブする型

整数などの**スタック上に収まる型**はコピーされます：

```rust
let x = 5;
let y = x;       // コピー
println!("{}", x); // OK！x はまだ有効
```

`String` のようなヒープを使う型はムーブします。`Copy` トレイトが実装されているかどうかが基準です。

## 借用（Borrowing）— 所有権を渡さずに使わせる

所有権を渡してしまうと呼び出し元では使えなくなります。「使わせるが所有権は渡さない」のが**借用**です。

```rust
fn print_str(s: &String) {   // & で参照を受け取る
    println!("{}", s);
}

let s = String::from("hello");
print_str(&s);               // & で参照を渡す
println!("{}", s);           // s はまだ有効！
```

`&String` は「String への参照」です。所有権は移動せず、関数が終わっても `s` は有効です。

### 可変借用

参照先の値を変更したい場合は `&mut` を使います：

```rust
fn add_world(s: &mut String) {
    s.push_str(", world");
}

let mut s = String::from("hello");
add_world(&mut s);
println!("{}", s); // "hello, world"
```

**重要な制約**：可変借用は同時に1つしか存在できません。

```rust
let mut s = String::from("hello");
let r1 = &mut s;
let r2 = &mut s; // ← エラー！可変借用は同時に1つだけ
```

これはデータ競合（2つの操作が同時に同じメモリを変更する問題）をコンパイル時に防ぐためです。

### 不変借用と可変借用は共存できない

```rust
let mut s = String::from("hello");
let r1 = &s;      // 不変借用
let r2 = &mut s;  // ← エラー！不変借用がある間は可変借用できない
println!("{}", r1);
```

「読んでいる最中に書き換えられる」と困るからです。

## ライフタイム — 参照は参照先より長生きできない

借用したものが参照先よりも長生きすると、**ダングリングポインタ**（消えたメモリを指すポインタ）になります。Rustはこれもコンパイル時に防ぎます。

```rust
fn main() {
    let r;               // r は外側のスコープで宣言（main が終わるまで生きる）
    {
        let x = 5;
        r = &x;          // r は x を借用
    }                    // ← x はここで消える（内側スコープの終わり）
                         //   でも r 自体はまだ main の中で生きている！
    println!("{}", r);   // r という変数は存在するが、r が指す x はもう消えている → 危険！
}
```

エラー：
```
error[E0597]: `x` does not live long enough
```

### 関数のライフタイム注釈

参照を返す関数では、「返した参照をいつまで使えるか」を呼び出し元が知る必要があります。

次の関数を例に考えます：

```rust
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}
```

戻り値は `x` か `y` のどちらかです。でも**シグネチャだけを見ると**どちらが返るか分かりません。`x` が先に消える場合も `y` が先に消える場合もありえます。呼び出し元は「返ってきた参照をいつまで使っていいか」が判断できません。

そのためこのままだとコンパイルエラーになります：

```
error[E0106]: missing lifetime specifier
```

`'a`（ライフタイムパラメータ）を付けることで「**`x` と `y` のうち寿命が短い方と同じ期間しか戻り値は使えない**」と明示します：

```rust
// 'a はライフタイムパラメータ（名前は何でも良い、慣例は 'a）
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

これにより、呼び出し元でライフタイムを超えた使い方をコンパイル時に検出できます：

```rust
let result;
let s1 = String::from("long string");
{
    let s2 = String::from("xyz");
    result = longest(s1.as_str(), s2.as_str());
    println!("{}", result); // OK: s1 も s2 もまだ生きている
}
println!("{}", result); // ← エラー！s2 は消えているので result も使えない
```

## まとめ

| 概念 | 意味 | 目的 |
|---|---|---|
| 所有権 | 値の持ち主は1人だけ | 二重解放の防止 |
| 借用（`&`） | 所有権を渡さずに参照 | 柔軟な関数引数 |
| 可変借用（`&mut`） | 変更可能な参照（同時に1つだけ） | データ競合の防止 |
| ライフタイム（`'a`） | 参照の有効期間の明示 | ダングリングポインタの防止 |

これらは全て「**コンパイル時にメモリ安全を保証する**」という1つの目標のためにあります。慣れるまでコンパイラと格闘しますが、慣れてくるとコンパイラが「なぜダメか」を的確に教えてくれるので、むしろ心強くなります。
